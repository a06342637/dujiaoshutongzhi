# 实机验收清单

## Docker（需要有 Docker 的 Linux 主机）

- [ ] amd64、arm64 分别构建成功；构建过程完成类型检查和自动化测试。
- [ ] 仅设置两个必填参数，命名卷自动创建；容器以非 root 身份运行。
- [ ] `/start` 可用，Bot 不暴露网站端口。
- [ ] 保存设置后重建容器，配置、快照、看板 ID 仍保留。
- [ ] 停止容器正常退出；旧版程序拒绝打开更高版本数据库。

## 网站与 Telegram（需要操作者自己的店铺和测试频道）

- [ ] 公开接口接入真实 v1.5.0 店铺；不修改网站文件。
- [ ] 测试不同 API 域名与网站域名。
- [ ] 添加管理员私聊、频道、群；非管理员不能打开管理菜单。
- [ ] 无发布权限时报明确错误；撤销权限后失败在运行状态可见。
- [ ] 逐商品普通表情、颜色、名称、排序、链接、规格展开正确。
- [ ] 自定义表情在有资格的私聊／群／频道显示；无资格时测试实际回退。
- [ ] 变化通知与看板独立开关；修改模板仅影响新通知和看板。
- [ ] 保持一条看板，分页可操作，普通读者只能翻页／刷新。
- [ ] 请求 1 秒检查、10 秒合并与立即通知分别符合预期；无并发重叠扫描。
- [ ] 人工、自动、上游、无限、隐藏、区间和多规格商品分别核对。
- [ ] 先建立基线，再用自有测试商品制造库存变化；不对公共演示店创建订单或修改库存。
- [ ] 断网不触发售罄；恢复后告警消除；失败目标不阻塞其他目标。
- [ ] 导出再导入，预览摘要并确认后配置一致；导出不含 Token。

## 版本与更新

- [ ] 主菜单、`/version` 和 `/settings` 显示当前应用版本。
- [ ] 设置中可以检查正式 Release，未发布更高版本时不出现升级按钮。
- [ ] 非管理员无法下载或触发更新。
- [ ] 更新下载失败时旧版本继续监测；完成后管理员收到成功消息。
- [ ] 新版无法就绪时旧版本恢复，商品配置、看板 ID 及库存记录保留。
- [ ] 使用同一数据卷重新创建容器后，仍使用最新应用版本。

## 交付环境说明

自动化测试不向 Telegram 或店铺发写请求。真实频道渲染、Telegram Premium／Fragment 权限、实际 Docker 容器与多架构镜像必须按本清单另行实测，未完成前不能宣称已通过。
